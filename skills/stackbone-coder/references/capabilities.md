# Capability checklist — walk it one at a time

After the type-specific interview, go through **every** capability below with the user, **one question each**: _do we need this?_ For each **yes**, note the surface, where it is reachable from, and what to add. Then read the surface's docs page and write the code from it: the page is titled like the surface under SDK (`stackbone.database`, `stackbone.rag`, …; `list_docs` for the path, then `get_doc`), and a helper with no page of its own (`requestApproval`, `callDeepAgent`, `stackbone.workflows.*`, `browserTools`) is found with `search_docs` on its name, area `sdk`. The **stackbone** skill holds the shapes and the rules; the page holds the API. Default everything to **no**: only wire what the user confirms.

Two facts that decide most of this:

- **Where am I calling from?** A tool body and a workflow `'use step'` can use almost every surface. A handful are **workflow-body only**.
- **The envelope rule.** Every surface returns `{ data, error }` (destructure and handle both branches) **except** `stackbone.database`, which is native Drizzle (rows back, throws on error), and `stackbone.connection(id)`, which throws a `ConnectorCallError`.

All of these are reached through the ambient client: `import { stackbone } from '@stackbone/sdk'`. Never wire credentials or connection strings; the runtime injects them.

## A. Available from a tool **or** a workflow step

Ask each as "Do we need to …?"

| #   | Ask                                                               | Surface                                                                                                                                                                                                                                                   | Adds                                                                                                                                                                                  |
| --- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **store / query data?** (records, vectors, full-text)             | `stackbone.database`: native Drizzle over the agent's Postgres (`pgvector` + `tsvector`)                                                                                                                                                                  | a Drizzle schema at `src/schema.ts`; a migration via `stackbone db migrate create`                                                                                                    |
| 2   | **upload / serve files?** (images, PDFs, exports)                 | `stackbone.storage`: S3-compatible object storage (MinIO in dev)                                                                                                                                                                                          | nothing to declare                                                                                                                                                                    |
| 3   | **make a one-off LLM call, embeddings, or images?**               | `stackbone.ai`: OpenAI-compatible chat / embeddings / images through the deployment's model provider                                                                                                                                                      | nothing; the provider is configured once in Studio                                                                                                                                    |
| 4   | **search ingested documents?** (RAG)                              | `stackbone.rag`: ingest + hybrid retrieval; ingest also via the durable `ingestDocuments(...)` from `@stackbone/sdk/workflow`                                                                                                                             | nothing to declare (the RAG schema is platform-provisioned)                                                                                                                           |
| 5   | **call a third-party API?** (Slack, email, a CRM)                 | `stackbone.connection(id).<op>(args)`: brokered by Stackbone Connect; **throws** `ConnectorCallError` (match `err.code`). From a durable `'use step'`, `callConnector(connector, operation, args)` from `@stackbone/sdk/workflow` is the same broker call | nothing to declare; the `id` is the connector's verbatim id, the one the operator gave it in Studio. In an **agent**, prefer `connectorTool({ connector, operation })` in `tools: []` |
| 6   | **use a versioned, editable prompt catalog?**                     | `stackbone.prompts`                                                                                                                                                                                                                                       | nothing to declare                                                                                                                                                                    |
| 7   | **read operator-tunable config?** (greeting, limits, toggles)     | `stackbone.config`: key-checked + typed                                                                                                                                                                                                                   | a Zod object at `config.schema.ts` (workspace root); `stackbone dev` turns it into the Studio editor + types                                                                          |
| 8   | **read operator-managed secrets?** (an API key the operator sets) | `stackbone.secrets`                                                                                                                                                                                                                                       | nothing in code; the operator sets the value in Studio                                                                                                                                |
| 9   | **read workspace settings the operator picks?**                   | `stackbone.settings` (read-only)                                                                                                                                                                                                                          | nothing                                                                                                                                                                               |
| 10  | **call another agent?** (delegate a sub-task)                     | from a workflow step: `callDeepAgent(name, input)` / `streamDeepAgent` from `@stackbone/sdk/workflow` → `{ text }`                                                                                                                                        | the sibling agent must exist in the workspace; **inside an agent**, compose with `subagents` on `defineDeepAgent` instead                                                             |
| 11  | **give the agent a real browser?**                                | `browserTools()` / `browserSubagent()` from `@stackbone/sdk/deep`                                                                                                                                                                                         | nothing to declare                                                                                                                                                                    |

> Note on #3 vs. the agent's own model: an **agent** already has a model bound in its `index.ts` for the conversation. Reach for `stackbone.ai` only for a _separate_ LLM call inside a tool or a step, or for embeddings / images.

## B. Workflow-body **only** (not available in an agent tool)

| #   | Ask                                                        | Surface                                                                                                  | Notes                                                                                                                               |
| --- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 12  | **pause for a human to approve / decide?** (HITL)          | `requestApproval({ token, topic, payload, timeout, fallback })` from **`@stackbone/sdk/workflow`**       | call from the workflow **body**, never inside a `'use step'`; needs the `workflow` peer; races the human decision against a timeout |
| 13  | **kick off or schedule other workflows?** (fan-out / cron) | `stackbone.workflows.start(name, input)` · `.startAndWait(name, input)` · `.schedule(name, input, cron)` | for ship-with schedules prefer the declarative `export const schedules = [...]` next to the workflow                                |
| 14  | **run one at a time, in arrival order?**                   | `executionMode: 'serial'` on the workflow's `stackbone.config.ts` entry                                  | only when overlapping triggers must not run in parallel                                                                             |

If the user wants to gate **an agent's tool** behind approval, that is NOT #12: it is `interruptOn: { <tool>: true }` on `defineDeepAgent` (same inbox, agent-side pause; `search_docs` `interruptOn`). #12 / #13 in a plain **agent** with no tool to gate is the signal it needs a **workflow** (or a workflow-agent): revisit the piece type.

## After the checklist

1. For each **yes**, read the surface's page and write the code there (a tool body or a workflow step), in the shapes the **stackbone** skill gives.
2. Add any declarations the table calls out: `src/schema.ts` and `config.schema.ts` (both at the workspace root). The agent itself is discovered by its `deep-agents/<name>/` folder; no manifest.
3. The peers live in the **root** `package.json`: `stackbone add agent` pins `deepagents` + `@langchain/*` for you; `workflow` is pinned by the shell.
4. Boot `stackbone dev` and exercise every wired surface before calling the piece done (the **stackbone-cli** skill).
